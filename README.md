# 双人录音复听分段

给编辑使用的双人录音复听网页：上传一段不超过 30 秒的 16 kHz 单声道 WAV，
为甲、乙两位说话人各标出 3～8 段互不重叠的参考语音，后端对整条录音做
短时声学分析，把每个非静音帧判给甲 / 乙 / 待复核，合并相邻同标签帧后
在时间轴上展示分段与置信度，点击任意片段即可跳转到原录音对应位置复听；
在复听页还可加配乐试听：配乐只在与讲话段重叠处自动压低，圈出的提示音保持原样。

## 快速启动（Docker Compose）

```bash
docker compose up --build
```

然后浏览器打开 <http://localhost:8000> 。

页面上的「载入演示音频」按钮会生成一段合成的双人录音并自动填好参考段，
可直接点击「开始分析」体验完整流程。

## 本地开发（不用 Docker）

```bash
pip install -r backend/requirements.txt
pip install -r backend/requirements-dev.txt   # 自测需要
uvicorn app.main:app --app-dir backend --reload
# 打开 http://localhost:8000
```

## 使用流程

1. **载入录音**：选择本地 WAV（≤30 秒、16 kHz、单声道），或点「载入演示音频」。
2. **标注参考**：在波形上按住拖动选择片段，点「设为甲参考 / 设为乙参考」；
   每人 3～8 段，所有参考段互不重叠；每段可单独试听、删除。
3. **开始分析**：时间轴上显示 甲（蓝）/ 乙（橙）/ 待复核（黄）/ 静音（灰）
   分段，颜色不透明度反映置信度；点击片段或明细表行跳转复听。
4. **配乐试听**：上传等长 16 kHz 单声道 WAV 作配乐，拖选片段并点
   「将当前选区设为提示音」，再点「生成配乐试听」查看增益曲线并试听。
   细节见下文「配乐试听」。

参考段越界、相互重叠、数量不足（<3 或 >8）、段长 <0.3 秒、
参考内有效语音不足、录音几乎全静音等情况，服务端会拒绝分析并返回中文原因。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | 健康检查 |
| GET | `/api/demo` | 返回演示 WAV（base64）与配套参考标注 |
| POST | `/api/analyze` | multipart：`file`=WAV，`references`=JSON `{"A":[[s,e],...],"B":[[s,e],...]}`（秒） |
| POST | `/api/mix` | multipart：`file`=录音 WAV，`music`=等长配乐 WAV，`segments`=分析结果分段 JSON，`cues`=提示音区间 JSON（秒） |

`/api/analyze` 响应：

```json
{
  "duration": 12.0,
  "frame_count": 1196,
  "frame_hop_ms": 10.0,
  "segments": [
    {"label": "silence", "start": 0.0, "end": 0.488, "confidence": 1.0, "frames": 49},
    {"label": "A", "start": 0.488, "end": 3.208, "confidence": 0.998, "frames": 272}
  ],
  "stats": {"A": 272, "B": 500, "review": 12, "silence": 412}
}
```

`label` ∈ `A`（甲）/ `B`（乙）/ `review`（待复核）/ `silence`（静音）。

`/api/mix` 响应（有解）：

```json
{
  "feasible": true,
  "duration": 12.0,
  "block_ms": 20.0,
  "block_count": 600,
  "speech": [false, true, "…"],
  "cue": [true, "…"],
  "limits": [1.0, 0.42, "…"],
  "gains": [1.0, 0.38, "…"],
  "mix_base64": "UklGR…",
  "mix_peak_before_scale": 0.87,
  "mix_scale": 1.0,
  "stats": {"blocks": 600, "speech_blocks": 468, "cue_blocks": 8,
            "ducked_blocks": 585, "min_gain": 0.0008, "max_gain": 1.0}

```

无解时返回 200 + `{"feasible": false, "gains": null, "message": "…", "conflicts": [...]}`，
`conflicts` 中每项为 `{label, start, end, reason}`，供前端一键跳回原声复听。

## 配乐试听

1. 在第 3 步完成分析后，上传一条与录音**等长**的 16 kHz 单声道 WAV 作配乐。
2. 在波形上拖出选区，点「将当前选区设为提示音」；提示音块不参与压低。
3. 点「生成配乐试听」：页面画出逐 20 ms 块的增益曲线（同时显示每块上限、讲话块、
   提示音块），并提供混音试听。

增益规划（`backend/app/duck.py`）：

- 录音按 20 ms（320 采样点）均匀切块，最后一块可不足 20 ms。
- 每块增益 `g ∈ [0, 1]`，相邻块最多下降 0.10、最多上升 0.04。
- 与甲 / 乙 / 待复核分段有重叠的块：压低后的配乐在 300～3400 Hz 的 RMS
  ≤ 同块原声同频带 RMS 的一半，因此该块上限
  `cap = min(1, 0.5 × 原声频带 RMS / 配乐频带 RMS)`（块内配乐静音则 cap = 1）。
  频带能量按块独立做零相位 4 阶 Butterworth 带通后计算，使“块内增益恒定”
  恰好可逐块换算。
- 提示音块要求 `g = 1`。
- 在全部约束下取**逐块最高**增益：可行域对逐点取最大值封闭，故存在唯一最大解，
  且任何可行解都逐点不超过它。实现为先从后向前收紧下降速率给出的上界，
  再从前向后收紧上升速率；若最大解在提示音块仍小于 1，则无解。
- 无解时把达到最小上界的块追溯到造成压缩的讲话块，返回对应讲话分段。
- 混音 = 原声 + 增益 × 配乐；若峰值超过满幅，两轨乘以同一缩放系数。

页面状态规则：换录音、改参考、换配乐、改选区（含清除选区）、重做分段时，
旧混音立即撤下（停止播放、释放 blob URL、隐藏面板）；所有分析 / 混音请求带
递增序号，迟到的响应一律丢弃，不能恢复旧试听。

## 算法说明（NumPy + SciPy）

1. **分帧**：25 ms 窗、10 ms 帧移（16 kHz 下 400/160 采样点）。
2. **特征**（`backend/app/features.py`）：预加重 → 汉明窗 → 功率谱 →
   26 通道 Mel 滤波器组 → log → DCT 得 13 维 MFCC，拼接一阶差分与对数能量，
   共 27 维短时特征。
3. **静音检测**（`classify.vad_mask`）：按帧 RMS 自适应取阈
   `max(1e-4, min(4×P10, 0.3×P95))`，低于阈值判静音。
4. **归属判断**（`classify.classify_frames`）：汇总每位说话人全部参考段内的
   非静音帧，标准化后各拟合一个对角协方差高斯模型；每个非静音帧比较两个
   模型的对数似然决定归属，似然差经参考帧自适应尺度转成置信度。
5. **待复核**：置信度 < 0.65（与两人参考相似度接近），或对两个模型的
   对数似然都明显低于参考典型值（谁都不像）的帧，标为 `review`。
6. **合并**（`classify.merge_segments`）：相邻且标签相同的帧合并为段，
   段置信度取帧均值。

## 交付核对

### 已实现
- FastAPI 后端：上传校验（WAV、16 kHz、单声道、≤30 s）、参考标注校验
  （3～8 段、不越界、不重叠、段长下限、参考内有效语音下限），全部以 400 + 中文原因拒绝。
- NumPy/SciPy 短时特征（MFCC + 差分 + 能量）、自适应静音检测、
  双高斯模型帧级归属、低置信 / 异常帧待复核标记、相邻同标签帧合并。
- 原生前端（无框架）：波形显示与拖动选区、参考段管理（试听 / 删除）、
  分段时间轴（标签 + 置信度）、点击片段跳转复听、分段明细表。
- 配乐试听：等长配乐上传与校验、提示音区间管理（波形高亮 / 试听 / 删除）、
  20 ms 块级增益规划（0～1、每块最多降 0.10 / 升 0.04、约束下取逐块最高）、
  300～3400 Hz 频带压低（≤ 同块原声一半）、提示音块固定增益 1、
  无解时定位冲突讲话段并提供原声复听、超满幅时两轨等比缩小、增益曲线绘制
  与混音 WAV 试听；换录音 / 改参考 / 换配乐 / 改选区 / 重做分段即撤下旧混音，
  请求序号保证迟到的响应不能恢复旧试听。
- 演示音频生成（合成双人语音 + 预填参考段），一键体验完整流程。
- Docker Compose 单服务交付（后端托管前端静态文件，含健康检查）。

### 已验证（本地自测，Python 3.11 + Node 22）
- `python -m pytest backend/tests`：31 项全部通过（原 13 项 + 新增 18 项），覆盖

    各说话时段内正确标签占非静音帧 ≥85%、误判为对方 ≤5%、回合间隙判为静音；
  - 静音输入：全静音录音返回 400「有效语音过少」；语音后的长静音尾正确标为静音段；
  - 低置信输入：第三说话人区域与双人混音区域均产生待复核帧，
    且待复核段置信度均 <0.65、正常归属段置信度约 0.97～0.98；

    超 30 秒、非 WAV、参考 JSON 无法解析，均返回 400 及中文原因；

    并核对速率 / 上限约束；讲话块被压低、静音处恢复为 1、下一讲话段前已预先降下；

  - 提示音：静音处提示音全块增益为 1；提示音离讲话太近或落在讲话中时返回无解，

### 未完成 / 限制
- 仅支持两人场景；模型为单高斯（每说话人一个对角协方差），
  对真实录音中多人音色相近、强噪声、重叠说话的区分能力有限，
  这类帧依赖“待复核”兜底，需人工确认。
- 未做帧标签的时序平滑（严格按需求只做相邻同标签合并），
  真实录音上可能出现短促的孤立段。
- 分析结果不持久化，刷新页面需重新上传分析。
- 配乐试听的“同块频带 RMS”按块独立零相位带通计算（块长 20 ms 时 4 阶
  Butterworth 的两侧过渡带约占块内十余个采样点），若改用全轨连续滤波再分块
  统计，块边界处会有邻块能量串扰，实测偏差在 10% 量级以内；如需严格按整轨
  滤波口径，应改用重叠分块 / 更短滤波器。
- 增益按块阶跃施加，块边界未做平滑斜坡；如需更平滑的听感可加短交叉淡化，
  但会略微偏离“块内恒定”的严格口径。
- 配乐仅在浏览器端做等长 / 时长校验，真正的 16 kHz、单声道、长度校验在服务端；
  浏览器无法解码时仍可提交，由服务端给出中文原因。
- 交付环境无 Docker 守护进程，镜像构建与 `docker compose up` 未在本机实际执行；
  Dockerfile 与 compose 配置按标准实践编写并经静态检查。前端集成测试使用 jsdom
  与真实 uvicorn，未在真实浏览器中点击验证。
